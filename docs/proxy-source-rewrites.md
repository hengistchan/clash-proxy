# Stash 远程代理源节点改写

打开「代理源 → 编辑 → 节点改写 · Stash」。每个远程来源可以保存最多 20 条改写规则，规则从上往下执行。

例如，只给名字以 `HK-` 开头的 Shadowsocks 节点补上 UDP：

- 节点名称正则：`^HK-`
- 协议类型：`ss`
- 操作：仅补缺失
- 节点字段：`udp`
- 字段值：开启（`true`）

名称正则使用 RE2，留空匹配全部名称；协议留空则不限。可改写 `udp`、`udp-over-tcp` 或 `tfo` 的布尔值。「仅补缺失」会保留已有字段，包括显式的 `false`；只有「覆盖已有值」才会更改它。字段是否生效仍取决于 Stash、节点协议和服务端能力。

先点「预览改写结果」可试跑当前编辑内容。工作台读取上游 YAML 的 `proxies` 列表，只返回节点数量及部分字段的前后差异；不保存规则，也不回传节点名称、上游地址、认证头或节点凭据。保存后，规则会随工作台版本一起记录和恢复。将同名来源重新导入当前配置时，复用已有来源绑定的同时也会保留已有改写规则。

含改写源的 Stash YAML（含设备订阅和 ZIP）会为每个改写源写入工作台链接；未启用改写的来源保持原样。下载 YAML 或 ZIP 时，如果没有 Stash 设备订阅链接，工作台会自动启用它。改写源链接只允许读取对应节点列表，不能下载整份配置。更换或撤销 Stash 设备订阅链接会让之前导出的改写链接失效；重新下载并导入后才会使用新链接。工作台的公开地址必须能被 Stash 访问，部署时可设置 `STASH_PUBLIC_BASE_URL`。

Stash 按自己的更新间隔请求代理源。工作台收到请求时才尝试拉取上游，同一个来源和规则组合在 60 秒内复用最近一次尝试。下载、解析或改写失败时，如果同一上游地址和认证头有上次成功的结果，就返回加密缓存中的结果（响应头 `X-Proxy-Source-Status: stale`）；否则返回错误。保存和导出主配置不会请求上游。改写目前只作用于 Stash 的远程代理源，支持 Stash / Clash YAML 的非空 `proxies` 列表。

如果服务端 DNS 返回 Fake IP，预览会明确提示来源地址被拦截。可按[远程来源 DNS 配置](shadowrocket-delivery.md)设置 `STASH_UPSTREAM_DOH_URL`；这项设置同时用于两个客户端的服务端来源下载。
