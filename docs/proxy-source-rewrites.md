# Stash 远程代理源节点改写

打开「代理源 → 编辑 → 节点改写 · Stash」。每个远程来源可以保存最多 20 条改写规则，规则从上往下执行。

例如，只给名字以 `HK-` 开头的 Shadowsocks 节点补上 UDP：

- 节点名称正则：`^HK-`
- 协议类型：`ss`
- 操作：仅补缺失
- 节点字段：`udp`
- 字段值：开启（`true`）

名称正则使用 RE2，留空匹配全部名称；协议留空则不限。`udp`、`udp-over-tcp` 和 `tfo` 是布尔快捷字段。选择「自定义字段」可以改写其他顶层字段，如字符串 `sni` 或数字 `port`，也可以选布尔值。字段名支持 1–64 个字母、数字、下划线或连字符，不支持路径；`name`、`type` 和对象保留字段不可改写。「仅补缺失」会保留已有字段，包括显式的 `false`；只有「覆盖已有值」才会更改它。字段是否生效仍取决于 Stash、节点协议和服务端能力。

先点「预览改写结果」可试跑当前编辑内容。工作台读取上游 YAML 的 `proxies` 列表，只返回节点数量及部分字段的前后差异；不保存规则，也不回传节点名称、上游地址或认证头。原始字段值只有布尔值会显示，原始字符串和数字会隐藏。保存后，规则会随工作台版本一起记录和恢复。将同名来源重新导入当前配置时，复用已有来源绑定的同时也会保留已有改写规则。

含改写源的 Stash YAML（包括设备订阅和 ZIP）会写入独立的工作台来源链接。来源链接只能读取对应节点列表。手动下载不会生成整份配置的设备订阅链接；撤销设备订阅也不会撤销新格式的独立来源链接。升级前发出的旧格式链接仍受原设备订阅令牌保护，更换或撤销旧令牌后需下载新版配置。工作台的公开地址必须能被设备访问，可用 `STASH_PUBLIC_BASE_URL` 指定。

同一配置内重新导入有效的工作台来源链接会还原上游绑定及改写规则。同一来源在恢复历史时保留其链接身份。跨配置复制、已撤销或不再存在的工作台引用会被拦截；可换回原始上游地址后重新绑定。工作台不会把自己的来源链接当成上游再代理。

「下载配置 → Stash」中可以查看设备版各托管来源的上次检查与成功时间。更换会立即使旧链接失效，撤销会暂停该来源对设备提供节点，直到重新启用。手动导入的设备需要下载并导入新文件；使用整份配置订阅的设备可刷新配置。其他来源和整份配置的订阅链接保持不变。

Stash 按自己的更新间隔请求代理源。工作台收到请求时才尝试拉取上游，同一个来源和规则组合在 60 秒内复用最近一次尝试。下载、解析或改写失败时，如果同一上游地址和认证头有上次成功的结果，就返回加密缓存中的结果（响应头 `X-Proxy-Source-Status: stale`）；否则返回错误。保存和导出主配置不会请求上游。改写目前只作用于 Stash 的远程代理源，支持 Stash / Clash YAML 的非空 `proxies` 列表。

如果服务端 DNS 返回 Fake IP，预览会明确提示来源地址被拦截。可按[远程来源 DNS 配置](shadowrocket-delivery.md)设置 `STASH_UPSTREAM_DOH_URL`；这项设置同时用于两个客户端的服务端来源下载。
